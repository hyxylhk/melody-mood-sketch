# 02 · 测试用例与验收标准

本项目有三层测试，从底向上分别是：

```
  scripts/smoke_test.py   端到端 —— 对着真实运行的服务发 HTTP 请求（36 项检查）
  tests/test_api.py       接口层 —— TestClient 模拟浏览器请求（不真开端口）
  tests/test_composer.py  单元层 —— 音乐合成引擎
  tests/test_emotion.py   单元层 —— 情绪分析算法
```

---

## 一、跑测试

```bash
# 单元测试 + 接口测试（不需要先启动服务）
pytest                      # 跑全部（47 条）
pytest -v                   # 显示每条用例名
pytest tests/test_emotion.py            # 只跑情绪分析
pytest tests/test_composer.py           # 只跑音乐合成
pytest tests/test_api.py                # 只跑接口
pytest -k "emotion"                     # 按名字筛选用例

# 端到端测试（需要先在另一个终端启动服务）
python run.py                           # 终端 1
python scripts/smoke_test.py            # 终端 2
```

当前实测结果：

```
47 passed, 1 warning in 3.4s        ← pytest
36 项通过 / 0 项失败                 ← smoke_test
```

> 测试会自动使用临时目录作为数据库（见 `tests/conftest.py`），
> **绝不会污染你真实的 `storage/diary.db`**。

## 二、功能演示用例（手动点，答辩现场照这个走）

### 用例 1：正向情绪 —— 喜悦

**输入**：点页面上的「😄 开心」示例，或手输：

```
今天项目终于上线了！熬了三个通宵，看到用户第一句夸奖的时候，
鼻子有点酸，但真的超级开心，一切都值了。
```

**预期结果**：

| 检查项 | 期望值 |
|--------|--------|
| 主情绪 | 😄 喜悦（joy） |
| 效价 valence | 约 **+0.85**（明显正向） |
| 唤醒度 arousal | 约 **0.72**（偏高） |
| 音乐 BPM | **116** |
| 音乐听感 | 大调五声音阶，明亮上行 |
| `source` 字段 | 配了 Key 显示 `llm`，没配显示 `local_rule` |

**接口级验证**：

```bash
curl -X POST http://127.0.0.1:8000/api/diary \
  -H "Content-Type: application/json" \
  -d '{"content":"今天项目终于上线了，超级开心，一切都值了！","auto_generate_music":true}'
```

返回体关键部分：

```json
{
  "id": 1,
  "emotion": {
    "primary": "joy",
    "primary_label": "喜悦",
    "primary_color": "#FFB020",
    "primary_icon": "😄",
    "tags": [],
    "valence": 0.85,
    "arousal": 0.72,
    "intensity": 0.6,
    "summary": "从「开心、超级开心」这些表达看，今天的底色是喜悦。",
    "source": "local_rule"
  },
  "music": { "id": 1, "status": "pending", "provider": "" }
}
```

### 用例 2：负向情绪 —— 孤独

**输入**：点「🌙 孤独」

```
又是一个人吃饭、一个人走路、一个人回到空荡荡的房间。
窗外的灯一盏盏亮起来，没有一盏是为我亮的。
```

**预期结果**：

| 检查项 | 期望值 |
|--------|--------|
| 主情绪 | 🌙 孤独（loneliness） |
| 效价 | 约 **-0.55** |
| 唤醒度 | 约 **0.24**（很低，慢） |
| 音乐 BPM | **58**（全场最慢之一） |
| 混响量 | **0.52**（空间感最强，像空房间） |

> **对比听用例 1 和用例 2 的音乐**：一个 116 BPM 明亮、一个 58 BPM 空旷，
> 这是"情绪真的驱动了音乐"最直观的听觉证据，现场一定要播对比。

### 用例 6：异常分支（答辩时展示健壮性）

| 操作 | 期望 |
|------|------|
| 只输入 1 个字然后提交 | 前端拦下并提示"至少写 2 个字" |
| `curl -d '{"content":"好"}'` 直接调接口 | HTTP **422** + JSON 报错详情 |
| 访问 `/api/diary/99999999` | HTTP **404** |
| 断网后提交日记 | 情绪自动降级为本地规则（`source=local_rule`），音乐照常生成 |
| 查不到日记却要生成音乐 | HTTP **404** |

### 用例 7：CORS 跨域（明确要求的验收项）

```bash
curl -i -X OPTIONS http://127.0.0.1:8000/api/diary \
  -H "Origin: http://localhost:5500" \
  -H "Access-Control-Request-Method: POST" \
  -H "Access-Control-Request-Headers: content-type"
```

响应头里必须包含：

```
access-control-allow-origin: *
access-control-allow-methods: DELETE, GET, HEAD, OPTIONS, PATCH, POST, PUT
access-control-allow-headers: *
```

另外，即使你用 `file://` 直接双击打开 `index.html`，也**不会**有跨域问题——
因为我们做了 `Access-Control-Allow-Origin: *` + 同端口托管前端两种兜底。

## 四、编写自己的新测试

新增 XXX 情绪最简单的方式（改动最小）：

1. 在 `backend/services/emotion_catalog.py` 的 `_EMOTION_PROFILES` 里加一个 `EmotionProfile`
2. 在 `tests/test_emotion.py` 里加一条样本断言，例如：

```python
def test_new_emotion():
    result = _local_rule_analyze("这里写触发这种情绪的句子")
    assert result.primary == "你的情绪代号"
```

3. 跑 `pytest tests/test_emotion.py -v` 验证
